# Jobs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Collage gets a `ServeHook` that fires only when `ListenAndServe` serves and whose ctx ends at the drain. A new plugin, `elagoht/jobs`, runs scheduled jobs and typed background queues on top of it.

**Architecture:**
- **Core:** a `ServeHook` interface and `Registry.Serve(ctx)`. `ListenAndServe` calls the hook after the port is bound, with a ctx that the drain cancels.
- **Plugin repo** `~/Desktop/collage-jobs`:
  - a cron parser that is pure and tested on its own;
  - a scheduler behind an unexported clock, so tests use a fake clock;
  - generic bounded queues with retries;
  - lifecycle (`OnServe`/`Start`/`Shutdown`) and config.

**Tech Stack:** Go 1.26, stdlib only.

**Spec:** `docs/superpowers/specs/2026-10-08-jobs-design.md`

## Global Constraints

- Never use the type `any`. Generic type parameters are fine.
- Core change is additive. Default behaviour is unchanged. Every existing test passes unchanged.
- Core does not add a public "run serve hooks" method. `Host` does not grow.
- Plugin conventions:
  - module `github.com/Elagoht/collage-jobs`, `go 1.26`, a comment above `module`;
  - `const Name = "elagoht/jobs"`, `New()` / `NewWith(cfg)`, `Version()` `"0.1.0"`;
  - README `# elagoht/jobs`, `.gitignore` (`*.test`, `*.out`);
  - `collage.json` like `~/Desktop/collage-errortrack/collage.json`;
  - no LICENSE.
- Config: `timezone` (IANA name, default `"UTC"`) and `disabled` (list of scheduled job names).
- Queue defaults:
  - `Workers` 1, `Capacity` 1000, `MaxAttempts` 1;
  - backoff 1s, 2s, 4s … capped at 1 minute;
  - errors `ErrQueueFull` and `ErrDraining`.
- Logging:
  - a run is Debug (name, duration);
  - a retried failure is Warn;
  - the last failure is Error;
  - each dropped-at-shutdown count is Warn per queue;
  - a skipped overlapping trigger is Debug.
- Panics on programming errors:
  - duplicate, empty or nil name or function;
  - definition after Init;
  - a bad cron expression (message names the field);
  - negative `Workers`, `Capacity` or `MaxAttempts` in `NewQueue`.
- Init errors (prefix `elagoht/jobs: `): unknown name in `disabled`, invalid `timezone`.
- Tests:
  - core: `go test -count=1 ./...` and `go test -race -count=1 ./internal/core/`;
  - plugin: `GOWORK=off go test -count=1 -race ./...`;
  - vet, gofmt and staticcheck clean.
- Commits:
  - stage files by name after reading `git status`;
  - trailer `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`;
  - no push or tag during the plan.

## Review Focus

1. **A job still running when its next trigger fires.** The trigger must be skipped, not queued up. A slow job must never pile up runs. Pinned in Task 3: `TestEvery_SkipsWhileRunning`.
2. **A cron time inside a DST gap or overlap (Europe/Istanbul has none, so use America/New_York).** The job runs exactly once per spec. Pinned in Task 2: `TestNext_DST`.
3. **`Enqueue` from a request while the drain has begun.** It must return `ErrDraining` at once, never block, and never be silently dropped. Pinned in Task 4: `TestQueue_EnqueueAfterDrain`.
4. **Shutdown with a full queue and a short ctx.** It must return when ctx ends, cancel running jobs' ctx and log the dropped count. It must never hang. Pinned in Task 5: `TestShutdown_DropsAndLogs`.
5. **A static `collage build` of an app using jobs.** No job may run and no worker may start. Pinned in Task 5: `TestBuild_RunsNothing`.

**Interfaces:**
- Produces (unexported, used by Task 3):

```go
type schedule interface {
	// next returns the first trigger strictly after t, in t's location.
	next(t time.Time) time.Time
}
type every struct{ d time.Duration }             // next = t.Add(d)
type cronSpec struct{ /* minute, hour, dom, month, dow bitsets; domStar, dowStar bool */ }
func parseCron(expr string) (cronSpec, error)    // error names the field: `cron "x": minute: ...`
```

**Behaviour:**
- **Fields:** minute 0-59, hour 0-23, day of month 1-31, month 1-12, day of week 0-6 (0 = Sunday; 7 is also accepted as Sunday).
- **Syntax:** `*`, `a`, `a-b`, `*/n`, `a-b/n`, and comma lists.
- **Rejected:** names (`MON`, `JAN`), `@hourly` and other macros, six-field expressions, and out-of-range values.
- **Day matching (Vixie):** if both day of month and day of week are restricted (neither is `*`), a day matches when EITHER matches; otherwise both must match.
- **next(t):**
  1. Start at t truncated to the minute plus one minute, in t's location.
  2. Walk forward field by field: month, then day, then hour, then minute, with wall-clock arithmetic via `time.Date` in the location.
  3. Give up after 5 years and return the zero time. Example: Feb 30 never matches.
- **DST:**
  - Gap: a wall time that does not exist, such as 02:30 on a spring-forward day, runs once at the first instant after the gap, 03:00 local. Detect it when `time.Date` normalises the hour forward.
  - Overlap: a wall time that occurs twice runs once, at its first occurrence. When walking minute by minute through the repeated hour, skip candidates whose wall clock was already produced by the earlier offset.
  - Implement this so the two cases in the test table pass. Do not try to match a particular cron implementation beyond them.

```go
type Config struct {
	Timezone string   `json:"timezone"`

}
func New() *Plugin
func NewWith(cfg Config) *Plugin
func (p *Plugin) Every(name string, d time.Duration, fn func(context.Context) error) *Job
func (p *Plugin) Cron(name, expr string, fn func(context.Context) error) *Job

func (p *Plugin) Start(ctx context.Context)     // same, for an app serving by itself; second call no-op
func (p *Plugin) Shutdown(ctx context.Context) error // Task 5 completes it
// internal for Task 4/5:
//   p.running context.Context  — the serve ctx, nil before start
//   p.draining() bool          — true once the serve ctx is done
//   p.workCtx / p.cancelWork   — parent ctx for every job run, cancelled at the end of Shutdown
//   p.wg sync.WaitGroup        — every run and worker
//   p.clock clock
//   p.register(name string)    — duplicate/empty/after-Init checks shared with queues
```

```go
type clock interface {
	Now() time.Time
	// After returns a channel that receives once d has passed.
	After(d time.Duration) <-chan time.Time
}
```

The fake clock is in `clock.go` behind an unexported constructor, with `Advance(d)` firing due channels in order. Tests reach it through an `export_test.go` that sets `p.clock`.

**Behaviour:**
- **Defining jobs:** `Every` and `Cron` panic on misuse (Global Constraints). `Cron` parses the expression at once and panics with the parse error.
- **Init:**
  1. Reads the config over `p.cfg` with `collage.PluginConfig`.
  2. Loads the timezone with `time.LoadLocation`; an invalid zone is an error.
  3. Checks `disabled` against the registered scheduled job names; an unknown name is an error.
  4. Marks the plugin as initialised.
- **OnServe(ctx) / Start(ctx):** only the first of these does anything (sync.Once).
  1. Store ctx as `p.running`.
  2. Create `workCtx` from `context.Background()`, cancelled by Shutdown.
  3. Start one goroutine per enabled scheduled job.
  4. Start the queue workers (Task 4).
- **Each scheduled job's loop:**
  1. If `RunOnStart`, run now.
  2. Loop: compute `next` from `clock.Now().In(loc)` and wait on `clock.After(next.Sub(now))` or `running.Done()`.
  3. On a trigger, if the previous run is still in progress (an `atomic.Bool`), log Debug "skipped" and continue. Otherwise start the run in its own goroutine tracked by `wg`, with ctx `workCtx`, wrapped in `context.WithTimeout` if `Timeout` is set.
  4. Recover panics and log them as failures.
  5. Log at Debug on success with the duration, and at Error on failure. Scheduled jobs are not retried.
  6. When `running` is done, the loop exits and starts no new runs.
- **Compile-time assertions:** `collage.Plugin` and `collage.ServeHook`.

### Task 4: Typed background queues

**Files:**
- Create: `queue.go`, `store.go`, `queue_test.go`
- Modify: `jobs.go` (queue registry: Start starts each queue's workers)

**Interfaces:**
- Consumes: from Task 3, `p.register`, `p.running`, `p.draining()`, `p.workCtx`, `p.wg`, `p.clock`, the logger, `ErrDraining`.
- Produces:

```go
var ErrQueueFull = errors.New("jobs: queue full")
type QueueOptions[T any] struct { // a type parameter, not the any type
	Workers     int
	Capacity    int
	MaxAttempts int
	OnFailure   func(ctx context.Context, item T, err error)
}
type Store[T any] interface {
	Push(item T) error            // ErrQueueFull when full
	Pop(ctx context.Context) (T, error) // blocks until an item or ctx done
	Len() int
}
type Queue[T any] struct{ /* unexported */ }
func NewQueue[T any](p *Plugin, name string, fn func(context.Context, T) error, opts QueueOptions[T]) *Queue[T]
func (q *Queue[T]) Enqueue(ctx context.Context, item T) error
```

Note: `[T any]` is a type-parameter constraint. The Global Constraint forbids the `any` TYPE as a value type, and constraints are explicitly fine. If you prefer, declare `type payload interface{}` and use `[T payload]`, but `any` as a constraint is allowed.

**Behaviour:**
- **Defaults:** Workers 1, Capacity 1000, MaxAttempts 1. Negative values panic.
- **The in-memory store** is a buffered channel of `Capacity`. `Push` does a non-blocking send and returns `ErrQueueFull` when the channel is full. `Pop` selects on the channel and ctx.
- **Enqueue:**
  - if `p.draining()`, return `ErrDraining` at once;
  - otherwise `store.Push`;
  - before serving, items wait in the queue.
- **Workers** start with the plugin, `Workers` goroutines tracked by `wg`. Each loop does:
  1. `Pop(popCtx)`. `popCtx` is a ctx that Shutdown cancels once the queue is empty or Shutdown's ctx ends (see Task 5). For now, use `workCtx`.
  2. Run `fn(workCtx, item)` with panic recovery.
  3. On failure, if attempts < MaxAttempts: log Warn, wait `backoff(attempt)` on `clock.After` or `workCtx.Done()`, and retry. The same worker retries, so ordering within one worker is kept.
  4. On the last failure: log Error, and call `OnFailure` if set, also with panic recovery.
- **backoff(n):** `min(time.Second << (n-1), time.Minute)`.

### Task 5: Shutdown, build safety, end to end

**Files:**
- Modify: `jobs.go`, `queue.go` (Shutdown)
- Test: `shutdown_test.go`, `e2e_test.go`

**Interfaces:**
- Consumes: everything above. From the core: `ServerConfig.DrainDelay`, `App.Shutdown`, `collage.NewBuilder`.

**Behaviour of `Shutdown(ctx)`:**
1. The scheduler loops have already stopped at the drain, because `running` is done. If Shutdown is called without a drain (Start's ctx still live), stop them now.
2. Queues: workers keep popping until each queue is empty or ctx is done. Implement this with a per-queue `popCtx` that is cancelled when `Len()==0`, observed as each worker finishes an item, or when ctx is done.
3. Wait on `wg` or ctx.Done(). If ctx ends first, call `cancelWork()` so running jobs see their ctx cancelled. Then wait for `wg` again, giving up after 1s more so a job that ignores its ctx cannot hang Shutdown, and log Warn if it gives up.
4. For each queue with `Len() > 0` left, log Warn `"jobs: dropped queued items"` with the queue name and count.
5. Return nil. Shutdown before any start returns nil at once.
