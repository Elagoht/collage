# Consent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new plugin, `elagoht/consent`, with four parts:
- a cookie-consent banner;
- a gate that holds scripts and iframes back until their category is granted;
- a JS API;
- opt-in, cache-safe server reading via `consent.Granted(rc, category)`.

elagoht/analytics also gains `consentCategory`, so the plugin can gate it.

**Architecture:**
- **Go side** (`consent.go`, `config.go`, `server.go`):
  - validates the config;
  - mounts an embedded `consent.js` and hoists one `<script defer>` tag into every page's head from `OnBeforeRender`, the same way analytics does;
  - on `serverPaths`, a middleware turns the cookie into a `collage.Vary("Cookie", combo)` dimension, which `Granted` reads.
- **JS side** (`consent.js`): the dialog, the gate, cookie read/write, GPC, and the `collageConsent` API.

**Tech Stack:** Go 1.26, stdlib only; plain ES2020 JS with no build step.

**Spec:** `docs/superpowers/specs/2026-10-09-consent-design.md`

## Global Constraints

- **No `any`.** Never use the type `any`.
- **No core change.** collage stays at v0.57.0.
- **Plugin conventions** (copy from ~/Desktop/collage-analytics and ~/Desktop/collage-live, which embeds and mounts JS):
  - module `github.com/Elagoht/collage-consent`, `go 1.26`, with a comment above `module`;
  - `const Name = "elagoht/consent"`;
  - `New()` / `NewWith(cfg)`;
  - `Version()` returns `"0.1.0"`;
  - README titled `# elagoht/consent`;
  - `.gitignore`;
  - `collage.json` with the Config properties;
  - no LICENSE.
- **Cookie:**
  - name `collage_consent`;
  - value `v=<version>&c=<comma-joined sorted granted non-required categories>&t=<unix seconds>`;
  - attributes `Path=/; SameSite=Lax; Max-Age=<maxAgeDays*86400>`, plus `Secure` on https;
  - not HttpOnly.
- **Script URL:** `/_collage/consent/consent.js?v=<first 12 hex of sha256(file)>`. It is served with `Content-Type: text/javascript; charset=utf-8`, `X-Content-Type-Options: nosniff`, and a long cache: the mount's immutable header, given the hash. Find out how collage mounts set Cache-Control.
- **Validation** — `Init` errors, each starting with `elagoht/consent: `:
  - a category name not in `^[a-z0-9-]+$`;
  - a duplicate category;
  - no categories;
  - `version < 1`;
  - no text for the default locale, or a missing label for a category in it;
  - `maxAgeDays` outside 1..400;
  - a `serverPaths` entry without a leading `/`.
- **`Granted`:**
  - a required category gives true;
  - an unknown category gives false;
  - when the request is not varied (outside `serverPaths`, a static export, or a capture), it gives false. Outside `serverPaths` it also logs one Warn per category name.
- **Tests:**
  - `GOWORK=off go test -count=1 -race ./...`, plus vet, gofmt and staticcheck.
  - The JS tests run headless Chrome when it is found at `CHROME` or in the standard locations. Otherwise they `t.Skip`.
  - Before release, the JS tests must run, not skip, on this machine.
- **Commits:**
  - stage files by name after reading `git status`;
  - end with the trailer `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`;
  - no push or tag during the plan.

## Review Focus

1. **Nothing gated runs before consent, including on a static host or with the cookie cleared mid-session.** No gated script executes, and no gated iframe has a `src`. Pinned in Task 3, `browser: gate_inert_before_grant`.
2. **A cached `serverPaths` page with two visitors whose consent differs.** Each must see their own render, and the response must carry `Vary: Cookie`. A render that reads the cookie without varying must never be cached for both. Pinned in Task 4, `TestServer_CacheSplitsByConsent`.
3. **A hostile or malformed cookie.** Examples: `c=analytics,evil`, a huge value, `v=abc`, a duplicate `c=`, and percent-encoding. Each must count as "no decision" or "only the configured categories", never as a panic or a grant of an unknown category, on both the server and the JS side. Pinned in Task 4, `TestParseCookie_Table`, and in Task 3, `browser: malformed_cookie`.
4. **Text containing HTML or quotes in the config.** For example `body: "<img src=x onerror=alert(1)>"`. It must render as text in the banner and stay escaped in the data attribute. Pinned in Task 2, `TestHoist_EscapesText`, and in Task 3, `browser: text_is_text`.
5. **Focus and keyboard.** The dialog takes focus, Tab stays inside it, Escape closes it without deciding, and focus returns to where it was. Pinned in Task 3, `browser: focus`.

### Task 3: consent.js — banner, gate, cookie, API — with browser tests

**Files:**
- Modify: `consent.js`
- Create: `browser_test.go` (headless Chrome harness), `testdata/` if needed

**Behaviour** (spec §1; implement in plain ES2020, no dependencies):
- **Config.** Read it from `document.currentScript.dataset.consentConfig`, or from the script element found by its `src`, because with `defer` `currentScript` is set.
- **Cookie.** Parse with these rules (they must match Task 4's Go parser exactly):
  - split the value on `&`;
  - the keys are `v`, `c` and `t`, each exactly once; anything else, or a repeat, makes the cookie invalid;
  - `v` must be a positive integer equal to the configured version, otherwise it is "no decision";
  - `c` is comma-separated names; unknown names are dropped; at most 64 entries and 4096 bytes in total, otherwise invalid.
- **Decision state.** The granted set is the required categories plus the cookie's `c`.
- **GPC.** When there is no decision and `navigator.globalPrivacyControl === true`, the dialog opens with every non-required box unchecked. Accept all still grants everything.
- **Dialog.** Build it with `document.createElement`. All text is set with `textContent`, never innerHTML.
  - It has the title, the body, a policy link if one is set, and the Accept all, Reject all and Choose buttons.
  - Choose reveals one checkbox per category, with required ones checked and disabled, and a Save button.
  - Use `<dialog>` with `showModal()`. Escape closes it with no decision and does not write the cookie.
  - Focus moves into the dialog and returns to the previously focused element afterwards.
  - The style element is built and inserted by the script, with themable `--consent-*` custom properties.
- **Gate.**
  - For each `script[type="text/plain"][data-consent]` whose category is granted, in document order, create a real script. Copy every attribute except `type` and `data-consent`, and copy the text. Replace the node. For `src` scripts, set `async = false` to keep execution order.
  - For `iframe[data-consent][data-src]`, set `src` when the category is granted. Otherwise insert, once, a placeholder before the iframe: a `<button>` reading `text.placeholder` and `text.allow`, with `{host}` and `{category}` substituted via textContent. The button grants that one category.
  - An unknown category gets `console.warn` once per name and stays inert.
- **Saving.** Write the cookie with the spec format. Add `; Secure` when `location.protocol === "https:"`.
- **Withdrawal.** If any previously granted category becomes ungranted, call `location.reload()` after saving.
- **API.**
  - `window.collageConsent = { get, set, open }`.
  - `get()` returns the sorted granted array.
  - `set(obj)` merges, saves, applies the gate, and fires the event.
  - After every save, dispatch `new CustomEvent("collage:consent", {detail: grantedArray})` on `document`.
- **Openers.** A click on any `[data-consent-open]` opens the dialog; use event delegation so later-added links work.

**Browser test harness** (`browser_test.go`, following collage-live's approach; see the memory note in its repo or README):
- Find Chrome in this order: the `CHROME` env var, `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`, `google-chrome`, `chromium`. Skip if none is found.
- Start a real collage app on a free port (`127.0.0.1:0`, closed, then reused) with the plugin, and pages whose templates contain the gate markup and a tiny test script. The test script records events and POSTs JSON results to a test-only action, `/_test/result`, registered `WithoutCSRF`.
- Run `chrome --headless=new --disable-gpu --no-first-run --user-data-dir=<tmp> --virtual-time-budget=5000 <url>` per scenario. Wait for the result POST, with a 15s deadline.
- Scenarios drive the page with `?scenario=<name>` (the test script reads it) and call the API, because a headless run cannot click like a user. For focus and Escape, dispatch `KeyboardEvent`s and check `document.activeElement`.
- **Required scenarios:**
  - `gate_inert_before_grant` (Review Focus 1): no cookie and no decision. The gated inline script's side effect (`window.ran = true`) has not happened, and the iframe has no `src`.
  - `grant_runs_in_order`: `set({analytics:true})` runs two gated scripts in document order, `src` first and then inline. Record the order in a global array.
  - `cookie_format`: after `set`, `document.cookie` matches the spec regexp.
  - `version_bump`: a cookie with `v=1` when the config says 2 means the dialog is open on load.
  - `malformed_cookie` (Review Focus 3): `c=analytics,evil&v=1&t=1&v=2` means "no decision", the dialog opens and nothing is granted.
  - `placeholder_grants_one`: clicking the iframe's placeholder button (via `.click()`) grants only `media`.
  - `withdraw_reloads`: grant, then `set({analytics:false})`. A reload counter in sessionStorage increments.
  - `gpc_defaults`: inject `navigator.globalPrivacyControl = true` before the script runs, via an inline script placed earlier in the head. Open the dialog; the non-required checkboxes are unchecked.
  - `text_is_text` (Review Focus 4): a config body containing HTML does not create elements. Assert `dialog.querySelector('img') === null` and that `textContent` includes the literal.
  - `focus` (Review Focus 5): the dialog opens and `activeElement` is inside it. Escape closes it, `activeElement` returns to the previously focused button, and no cookie is written.
  - `open_link`: clicking `[data-consent-open]` after a decision reopens the dialog.

### Task 4: Server-side reading

**Files:**
- Create: `server.go` (cookie parser, middleware, `Granted`), `server_test.go`
- Modify: `consent.go` (Init registers the middleware with `host.Use` when `ServerPaths` is non-empty)

**Interfaces:**
- Consumes: Task 1's `Config`/`required`; `collage.Vary(r, header, value) error`; `collage.Varied(rc, header) (string, bool)`; `collage.IsCapture`.
- Produces:

```go
func Granted(rc *collage.RenderContext, category string) bool
// unexported:
func parseCookie(value string, version int, known func(string) bool) (granted []string, ok bool)
func underPaths(path string, prefixes []string) bool
```

`Granted` is a package-level function, so it needs the plugin's config. Store the active config in the request context from the middleware, or keep a package-level registry keyed by app. Choose the simplest race-free form and explain it. Prefer having the middleware put the plugin pointer into the request context. Note, though, that context values are stripped in cached renders (see `collage.Vary` docs). Store the combo via `Vary`, which survives, and read the config from a package-level atomic set at Init, because there is one consent plugin per process. Document the limit.

**Behaviour:**
- **`parseCookie`:** the same rules as the JS (Task 3). Return the sorted, deduplicated known non-required categories.
- **`underPaths`:** segment-aware. `/shop` matches `/shop` and `/shop/x`, but not `/shopping`. The prefix `/` matches everything.
- **Middleware:** for a request under `serverPaths`, read the cookie, compute the combo (comma-joined, sorted, empty if none), and call `collage.Vary(r, "Cookie", combo)`. On an error from Vary, log a Warn and continue.
- **`Granted`:**
  - a required category gives true;
  - an unknown category gives false;
  - otherwise `combo, ok := collage.Varied(rc, "Cookie")`. When `!ok`, the result is false: warn once per category, unless `collage.IsCapture(rc.Context())`, or `rc.Request` is nil (a build render). When ok, the result is whether the category is in the combo.

  - `TestUnderPaths`.
  - `TestServer_CacheSplitsByConsent` (Review Focus 2): a page at `/shop`, `Incremental(time.Hour)`, cache enabled, and a data handler rendering `Granted(rc,"analytics")`.

    - Both responses carry `Vary: Cookie`.
  - `TestGranted_OutsidePathsWarnsOnce`: two calls give false, and the captured logger holds one Warn.
  - `TestGranted_Required`.
  - `TestGranted_StaticExport`: a build renders false with no warning.
