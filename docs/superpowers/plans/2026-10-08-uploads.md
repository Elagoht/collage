# Uploads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Collage gains `WithStreamingBody()`: the core never parses that action's body, and its CSRF token comes only from the header.
- A new plugin, `elagoht/uploads`, receives, validates, stores and safely serves uploaded files, over either a parsed form or a stream.

**Architecture:**
- Core:
  - a flag on `types.Action`;
  - a router registration check;
  - a header-only CSRF verify;
  - the action path skips any body read when the flag is set, and maps a body that hit its bound to 413.
- Plugin repo `~/Desktop/collage-uploads`:
  - `Store` and `Dir` (disk);
  - key and name helpers;
  - a sniffing, size-counting, hashing reader;
  - `Receive` with two paths (parsed form, or `MultipartReader`) and an all-or-nothing cleanup;
  - a safe `Handler`.

**Tech Stack:** Go 1.26, stdlib only.

**Spec:** `docs/superpowers/specs/2026-10-08-uploads-design.md`

## Global Constraints

- **No `any`.** Never use the type `any`.
- **Core change is additive.** Actions without the flag behave exactly as before, and every existing test passes unchanged.
- **Plugin conventions:**
  - module `github.com/Elagoht/collage-uploads`, `go 1.26`, a comment above `module`;
  - `const Name = "elagoht/uploads"`, `New(store)` / `NewWith(cfg)`, `Version()` returning `"0.1.0"`;
  - README titled `# elagoht/uploads`; `.gitignore` containing `*.test` and `*.out`;
  - `collage.json` shaped like ~/Desktop/collage-errortrack/collage.json;
  - no LICENSE.
- **Errors:** `ErrTooLarge`, `ErrType`, `ErrTooMany`, `ErrUnexpectedField`, `ErrAlreadyRead`, and `*uploads.Error{Field string; Err error}`. Messages are prefixed `elagoht/uploads: `.
- **Defaults:**
  - `MaxFiles` 1;
  - empty `Types` means any type;
  - non-file values are capped at 64 KiB in total;
  - the sniff window is 512 bytes.
- **Keys:** 32 hex chars of `crypto/rand` (128 bits), then the sniffed type's extension (`.png`, `.jpg`, `.gif`, `.webp`, `.pdf`, `.txt`, otherwise `.bin`).
- **Names:** the base name, with control characters and `/` `\` removed, truncated to 255 bytes on a UTF-8 boundary, and never used as a path.
- **`Dir`:**
  - the directory is 0700 and files are 0600;
  - writes go to a temp file in the same directory, then a hard link (exclusive create plus copy where links are unsupported);
  - an existing key is an error;
  - a key containing `/`, `\`, `..` or a control character is refused.
- **`Handler` headers:**
  - `Content-Type` re-sniffed from the stored file;
  - `X-Content-Type-Options: nosniff`;
  - `Content-Security-Policy: sandbox`;
  - `Content-Disposition: attachment` for everything except png, jpeg, gif and webp;
  - `Cache-Control: private, max-age=0` by default, configurable through `HandlerOptions{CacheControl string}`;
  - an unknown or refused key is 404.
- **Config:** `{"elagoht/uploads": {"dir": "var/uploads"}}`, used when built with `New(nil)`.
- **Tests:**
  - core: `go test -count=1 ./...` and `go test -race -count=1 ./internal/...`;
  - plugin: `GOWORK=off go test -count=1 -race ./...`;
  - vet, gofmt and staticcheck clean.
- **Commits:**
  - stage files by name after reading `git status`;
  - add the trailer `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`;
  - no push or tag during the plan.

## Review Focus

1. **The client lies about the file.** HTML or SVG sent as `image/png` with a `.png` name must be typed by sniffing, refused by an image-only rule, and never served inline. This is pinned in Task 3 (`TestReceive_SniffTraps`) and Task 4 (`TestHandler_SVGIsAttachment`).
2. **A stream that ends mid-file**, whether from a client disconnect or the body limit, leaves no file in the store and no temp file on disk. This is pinned in Task 3 (`TestReceive_TruncatedLeavesNothing`) and Task 5 (`TestE2E_BodyLimitLeavesNothing`).
3. **Exactly `MaxSize` bytes** is accepted; one byte more is refused, and nothing is stored. This is pinned in Task 3 (`TestReceive_MaxSizeBoundary`).
4. **A plain HTML form posted to a streaming action** gets a 403 whose message says the token must be sent in the header. It does not get a 500. This is pinned in Task 1 (`TestStreamingBody_FormTokenRefused`).
5. **Memory stays flat on a large streamed upload.** A 100 MB upload must not grow the heap by more than a few MB. This is pinned in Task 5 (`TestE2E_StreamingMemoryFlat`).

**Interfaces:**
- Produces:
  - `types.Action.StreamingBody bool`
  - `(*collage.ActionBuilder).WithStreamingBody()`
  - `router.ErrStreamingBodyMethod`, aliased as `collage.ErrStreamingBodyMethod`

**Behaviour:**
- `RegisterAction` refuses `StreamingBody` when no method is POST, PUT or PATCH. The error is `fmt.Errorf("%w: action %q declares %v", ErrStreamingBodyMethod, name, methods)`.
- `VerifyHeader(r)` is `Verify` without the form fallback:
  - the origin check, the cookie and the token validity are the same as in `Verify`;
  - it reads the token from `g.headerName`, and only from there;
  - a missing header returns `ErrHeaderRequired`, a new error whose message reads "the CSRF token must be sent in the <header> header for this action".
  - Keep `Verify` unchanged.
- In the action path, when `action.StreamingBody` is true:
  - the CSRF check calls `VerifyHeader`;
  - nothing calls `ParseForm` or `ParseMultipartForm`;
  - the `MultipartForm.RemoveAll` defer stays harmless, since it is nil;
  - `boundBody` still applies.
- **413 mapping.** After the handler returns an error, if `r.Body` is a `*limitedBody` with `tooLarge == true`, answer with `http.StatusRequestEntityTooLarge` and `actionBodyTooLarge(action, limit)` instead of the handler's error.
  - Apply this to every action, not only streaming ones. Check whether a non-streaming action can already reach it. If doing it for all actions would change existing behaviour, limit it to streaming actions and say so in the report.

type Store interface {
	Put(ctx context.Context, key string, r io.Reader) (int64, error)
	Open(ctx context.Context, key string) (io.ReadCloser, error)
	Delete(ctx context.Context, key string) error
}

var ErrBadKey = errors.New("elagoht/uploads: invalid key")
func Dir(path string) Store
// unexported, used by Tasks 3 and 4:

func cleanName(name string) string

**Behaviour of `Dir`:**
- **Put:**
  1. Validate the key; an invalid one returns `ErrBadKey`.
  2. Create the directory with 0700 if it is missing.
  3. If the target exists, return `ErrExists`, checked with Lstat.
  4. Create the temp file with `os.CreateTemp(dir, ".upload-*")` and chmod it to 0600.
  5. Copy, honouring ctx cancellation: check `ctx.Err()` between reads with a small loop, or wrap the reader with a ctx-aware reader.
  6. Sync, close, then link the temp file to the target with `os.Link` (link fails on an existing file, which makes the create atomic), and remove the temp file.
  7. If anything fails, remove the temp file.
- **Open:** validate the key, then `os.Open`. A missing file returns `fs.ErrNotExist`.
- **Delete:** validate the key, then `os.Remove`. A missing file is not an error.

### Task 3: `Receive`, over both paths

**Files:**
- Create: `uploads.go` (Plugin, Config, New/NewWith, Init), `receive.go`, `reader.go` (the counting, sniffing and hashing reader), `receive_test.go`

**Interfaces:**
- Consumes: Task 2's `Store`, `newKey`, `cleanName` and `extensionFor`; `collage.RenderContext` (`rc.Request`); `collage.PluginConfig`.
- Produces:

```go
const Name = "elagoht/uploads"
type Config struct{ Dir string `json:"dir"` } // Dir: the disk store used when New(nil)
func New(store Store) *Plugin
func NewWith(cfg Config) *Plugin
type Rules struct {
	MaxSize  int64    // bytes per file; 0 means no per-file limit (the body limit still applies)
	MaxFiles int      // per field; 0 means 1
	Types    []string // sniffed media types allowed; empty allows any
}
type FieldSpec struct{ /* unexported */ }
func Field(name string, rules Rules) FieldSpec
type File struct{ Key, Name, Type, SHA256 string; Size int64 }
type Received struct {
	Files  map[string][]File
	Values url.Values
}
type Error struct{ Field string; Err error }
func (e *Error) Error() string
func (e *Error) Unwrap() error
var ErrTooLarge, ErrType, ErrTooMany, ErrUnexpectedField, ErrAlreadyRead error
func (p *Plugin) Receive(rc *collage.RenderContext, fields ...FieldSpec) (*Received, error)
func (p *Plugin) Store() Store
```

**Behaviour:**
- **Path choice.** If `rc.Request.MultipartForm != nil`, read from it: `MultipartForm.File[name]`, then open each `*multipart.FileHeader` and stream it through the same reader. Otherwise call `rc.Request.MultipartReader()` and walk the parts. A non-multipart request with no files returns empty results, and `Values` comes from `PostForm` if that is already parsed.
- **Already read.** Mark the request as consumed with a context value or a field on the request. Use a small per-request marker in a `sync.Map` keyed by `*http.Request`, cleaned up when Receive returns, or a context value. A second `Receive` on the same request returns `ErrAlreadyRead`. Choose the simplest race-free form and explain it in a code comment.
- **Per file:**
  1. Read up to 512 bytes into a buffer and sniff with `http.DetectContentType`. Read 0 bytes means `application/octet-stream`.
  2. Strip parameters (`; charset=...`) when comparing against `Types`.
  3. If `Types` is non-empty and does not contain the sniffed type, return `ErrType` before storing anything.
  4. Otherwise `key := newKey(sniffed)`. `store.Put(ctx, key, reader)`, where the reader is `io.MultiReader(bytes.NewReader(sniffBuf), rest)` wrapped by a counting reader that fails with `ErrTooLarge` once more than `MaxSize` bytes have been read (exactly `MaxSize` passes), and a `sha256` tee.
  5. If Put fails because of the size limit, the reported error is `ErrTooLarge`, and Put has left nothing behind (Task 2's guarantee).
- **Fields.**
  - A part with a filename in an undeclared field returns `ErrUnexpectedField`.
  - More than `MaxFiles` files in a field returns `ErrTooMany`. Check this at the (MaxFiles+1)th file, before storing it.
  - Non-file parts go to `Values`, read with a cap of 64 KiB in total across all of them. Exceeding the cap returns `*Error{Field: name, Err: ErrTooLarge}`.
- **All or nothing.** Keep the keys stored so far. On any error, including a read error from a disconnect or a `*http.MaxBytesError`, `store.Delete` each stored key using a fresh `context.Background()` with a 5s timeout, then return the error. A `*http.MaxBytesError` is returned as-is, wrapped, so the core maps it to 413 (Task 1).
- **Errors.** Every rule error is `*Error{Field, Err}`.
- **Plugin.**
  - `New(store)` keeps the given store.
  - `NewWith(cfg)` / `New(nil)` builds `Dir(cfg.Dir)` in Init. The default dir is `"var/uploads"` after `PluginConfig`.
  - Init with neither a store nor a dir returns an error.
  - Assert at compile time that the type implements `collage.Plugin`.

### Task 4: `Handler`, README, collage.json

**Files:**
- Create: `handler.go`, `handler_test.go`, `README.md`, `collage.json`

**Interfaces:**
- Consumes: `Store`, `validKey` (Task 2).
- Produces:

```go
type HandlerOptions struct{ CacheControl string } // default "private, max-age=0"
func (p *Plugin) Handler(opts ...HandlerOptions) http.Handler
```

**Behaviour:**
1. The key is the last path segment, taken with `path.Base` of the URL path after the mount prefix. Use `r.URL.Path` and strip everything up to and including the last `/`.
2. If `!validKey(key)`, answer 404.
3. `store.Open`. `fs.ErrNotExist` is 404; any other error is 500, and it is logged.
4. Read 512 bytes and sniff. Then set the headers from the Global Constraints. Inline (no `Content-Disposition`) only for `image/png`, `image/jpeg`, `image/gif`, `image/webp`.
5. Copy the sniffed bytes and the rest of the file. Support HEAD with headers only. Other methods get 405 with `Allow: GET, HEAD`.
